# Media Studio v1 — 使用与验收

新版后台位于 `/studio/`，和原 `admin.html` / `admin-imgtc.html` 并存。

## 部署方式
当前处于草稿 PR，先检查 Cloudflare Pages 是否生成分支预览部署。**不要使用 GitHub 主分支的正式域名假定新版已经上线**。如有预览域名，在其后追加 `/studio/`。

只有 PR 合并或手动发布到 Production 后，`https://my-image-bed.pages.dev/studio/` 才应成为正式访问路径。

## 登录
使用 Cloudflare Pages Production/Preview 对应的 `BASIC_USER`、`BASIC_PASS`。新版后台的登录凭据只保存在网页运行内存，页面刷新后会消失。请务必为预览环境也绑定 `img_url` KV，否则预览数据不会完整。

## 现有功能（相册管理更新版）
- 分页加载记录，按文件名、标签、旧版相册标签、分类和排序
- **多级虚拟相册**：创建、重命名、调整父级、删除空相册；左侧目录树及窄屏下拉切换
- 选择文件夹时显示其中及下级文件夹的图片；可查看未归类素材
- 选择素材后可批量移入文件夹或移回未归类状态（一次最多 50 个）；图片原 URL 永远不变
- 预览图片、视频，复制图片真实链接
- 当前筛选结果全选，以及顺序遍历剩余 KV 页面后跨页选中（最多自动遍历 100 页）
- 批量收藏/取消收藏、添加/移除标签、添加/移除相册、设置分类
- 批量发布给 AI / 撤销发布；操作分批最多 50 条并反馈进度与失败项目
- 基于现有 `/upload` 端点批量上传并刷新页面；新上传默认不收藏、不发布

## 数据规则
- `liked`：个人收藏（**不自动公开到 AI 目录**）
- `aiPublished`：人工明确授权 AI 目录列出该图片
- `tags`：字符串数组，逻辑标签
- `albums`：旧版字符串数组标签式相册（兼容保留；可多选）
- `folderId`：新版单一虚拟文件夹 ID，稳定关联 `studio:folder:<id>` KV 记录；每张媒体至多归属一个文件夹
- 新版相册支持树状父子关系，同一张媒体通过标签仍可在多个筛选条件中出现
- `category`：单一分类字符串
- 黑名单和 NSFW 项目不会出现在 AI 目录
- AI 目录目前只索引图片，不索引视频

## 重要安全提示
- 现有公开图片 URL 仍可能被任何知道 URL 的人访问，`liked` 或相册并不提供私密存储权限。
- `/studio/` 是静态登录页面，不返回后台数据；后端 API 必须通过 Cloudflare 后台 HTTP Basic 认证。
- `/upload` 使用项目原有配置。若先前为了修复 401 而移除了 `UPLOAD_BASIC_USER/PASS`，上传接口**仍然是公开的**；此 PR 没有修复上传授权。
- 预览环境的数据和生产环境 KV 绑定可能不同，请确认后再批量操作。

## 验收检查
1. 使用预览地址 `/studio/` 登录，看见现有素材
2. 勾选多个媒体，并执行批量收藏，检查每个收藏状态
3. 跨页加载后仍保留选中状态，测试“选择全部匹配结果”
4. 创建「工作项目」及其子相册「Shopify 店铺 A」，选择多张素材批量移入子相册，刷新后状态保留
5. 重命名相册、修改父级，然后尝试删除非空相册，验证删除被拒绝
6. 给一张图片收藏但不发布 AI，公开目录不得出现该图片
7. 选择另一张图片发布 AI，确认目录返回且图片 URL 可以访问
8. 撤销发布后，公开目录应不再列出该图片
9. 验证旧 `/admin-imgtc.html`、上传页和已有 `/file/<id>` 链接没有受影响
