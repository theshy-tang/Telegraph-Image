# Studio 大图库渲染验证 — 2026-11-17

本轮只优化前端渲染，其他新增业务模块按用户要求暂缓。基线为 04fe713 的主网格实现；使用同样 1504 条本地隔离样例，分页全部加载后比较。

| --- | --- | --- |
| 已加载 / 匹配素材 | 1504 / 1504 | 1504 / 1504 |
| 桌面测试位置的挂载卡片 | 1504 | 16 |
| 桌面末尾，含离屏保留焦点 | 全量 | 17 |
| 窄屏末尾，含保留焦点 | 未单独测量 | 11 |

这些数字是 DOM 卡片数，随视口和滚动位置变化；不是耗时、帧率、进程内存或网络流量的改善百分比。普通图片样例由本地服务返回 1 像素图片，不能代表真实大图的下载、解码或 GPU 消耗。

## 实现

- 主网格匹配超过 200 项时，仅挂载视口附近的行，前后两行预留，顶部/底部占位保持完整滚动高度。
- 桌面固定卡片高 260px；540px 以下为 220px。实际验收四列桌面总网格高 104885px；两列窄屏为 173701px，与 1504 项的行高和间距公式一致。
- 滚动通过 passive 监听并合并到 requestAnimationFrame；只更新卡片窗口，不重跑标签、排序、统计等全量工作。
- 虚拟模式缓存最多为 max(96, 当前可见及保留焦点的卡片数)。小列表保持原全量布局；缓存不会像原先那样因所有数据都被视为可见而无限增长。
- 选择保存在 ID 集合中，与挂载卡片无关。选中/取消选中复用当前筛选结果，避免再筛选和排序一次。
- 方向键、Home/End 可以跨未挂载项导航；离屏焦点最多额外保留一张卡片，避免滚动卸载造成焦点丢失。卡片提供总数/位置属性，虚拟滚动关闭逐张 live 广播，筛选总数仍作为 status 通知。
- 全库检索卡片增加 content-visibility 提示，减少长结果列表的离屏布局/绘制工作；该对话框目前仍保留已加载结果的 DOM，未声称同样虚拟化。

## 验证

- npm test：244 项通过，新增 5 项窗口几何与导航回归。覆盖十万项的有界窗口计算、部分行、前后占位总高、双列响应、越界及首尾导航；十万项不是浏览器加载基准。
- 浏览器真实加载 16 页共 1504 项。Home/End 到达第 1 / 1504 项；滚动后节点保持有界，离屏焦点保留。
- 首尾各选一项并批量收藏，成功 2 项；全选当前结果仍为 1504；筛选 Fixture 1499 后只有 1 张，清除后恢复全量数据。
- 临时窄屏视口验证双列、220px 卡高与第 1504 项可达，页面无水平溢出；验收后已恢复默认视口。
- 原 C 混合相册逻辑、原始 URL、上传与数据 API未改变。所有写入仅发生在隔离样例存储。

## 复现

在项目目录使用 PowerShell 设置 STUDIO_FIXTURE_PORT=8088、STUDIO_FIXTURE_MEDIA_COUNT=1500，然后运行 npm run test:studio:serve。使用 test/e2e/studio-server.js 中的固定样例账号登录，每次点击加载更多直到已加载 1504 项。它们是可丢弃的本地样例，不使用真实凭据。

## 仍然存在的性能边界

尚未生成服务端轻量缩略图或视频封面；卡片继续使用原文件和现有 Preview 代理，因此单张大文件下载体积不变。未启用付费图像变换、外部图片服务或新存储。浏览器保留已加载的元数据，筛选/排序仍随已加载数据量增长；全库检索继续使用服务端分页。虚拟网格应使用页面搜索或方向键查找离屏素材，浏览器页面内查找无法扫描未挂载节点。
